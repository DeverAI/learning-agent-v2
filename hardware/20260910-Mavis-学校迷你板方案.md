# 学校迷你板硬件方案（ESP32 vs K210 选型 + 落地路线）

> 日期：2026-09-10 ｜ 作者：Mavis ｜ 状态：调研方案稿（待用户拍板后立项）
> 关联资产：学习Agent 服务器（daily-quote/笔记/讲课）、zhongkao-widget（countdown/calendar/quotes/schedule 配置结构）

## 0. 结论先行（TL;DR）

- **主控选 ESP32-S3，不选 K210/K230**。嘉楠（Canaan）已于 **2025-06-23 整体关停 Kendryte AI 芯片业务**（K210/K510/K230 全部停产，无后续支持路线图）。K210 无 WiFi/BLE，做联网显示板先天缺一条腿；现在为新品立项选 Kendryte = 选一条已死的供应链。
- **显示选电子墨水屏（e-ink），不选 OLED/LCD**：教室长亮场景只有 e-ink 能做到"无光害 + 数周续航 + 阳光下可读 + 断电内容不丢"。
- **最省事路径**：买 LilyGo T5 4.7 寸 e-Paper（ESP32-S3 版本，约 ¥300 级），一块板全集成（屏+主控+电池接口+RTC），固件成熟库多。
- **最便宜/最教学路径**：ESP32-S3 DevKit（约 ¥40）+ Waveshare 2.13/2.9 寸 e-ink 模块（约 ¥50-80）自组，面包板即可起步。
- **前提自检**：如果只是"想看倒计时/课表/每日一句"，手机/平板 + 服务器 PWA 是**零硬件成本**的现有解（学习Agent 首页 + /download 已上线）。迷你板的真实价值 = 无手机干扰、随手可看、电子班牌/桌面牌场景。先确认要真硬件，再往下读。

## 1. 需求定义（学校场景约束）

| 约束 | 推论 |
|------|------|
| 教室/课桌环境，可能长期无充电条件 | 功耗优先 → e-ink + 深睡，目标月级续航 |
| 上课静音、不分心 | 无喇叭无动画；静态信息展示 |
| 靠窗强光/普通日光灯 | e-ink 反射式，阳光下最好读 |
| 尺寸：笔袋/桌面牌 | 2.13-4.7 寸；电子班牌可到 7.5 寸 |
| 数据来自学习Agent 服务器 | WiFi（2.4G）拉取；无校园网时手机热点/离线预设 |
| 使用者是学生本人或班级 | 3 键交互（翻页/刷新/模式）；不需要触摸屏（贵且费电） |

核心功能（第一批，克制）：
1. 中考/大考倒计时（复用 zhongkao-widget 语义：`{name, target_date}`）
2. 今日课表 + 下一节课
3. 每日一句（复用 /api/daily-quote）
4. 手动刷新 / 自动定时刷新
5. 低电显示 + 充电提醒

可选第二批（先不做）：专注模式联动提醒、老师从服务器下发公告、LED 呼吸灯提示新消息。

## 2. 芯片选型对比（调研结论）

| 维度 | **ESP32-S3（推荐）** | K210（Sipeed Maix） | K230（CanMV） |
|------|---------------------|---------------------|---------------|
| 厂商状态 | 乐鑫，活跃，全球主流 | **嘉楠 Kendryte 部门已于 2025-06 关停** | 同左，已停产 |
| 无线 | WiFi 2.4G + BLE 5 内建 | **无**（需外挂 ESP8266/串口） | 部分成品板外挂 |
| 定位 | 通用物联网 MCU | 老式边缘视觉 AI | 更强边缘 AI（6 TOPS） |
| 开发 | Arduino/ESP-IDF/MicroPython，资料海量 | MaixPy（社区仍在但停滞） | CanMV（MicroPython），中文文档为主 |
| 典型板价 | DevKit ¥35-50；成品 T5 ¥300 级 | Maix Bit 余货 ¥100 上下（清库存） | CanMV-K230 板 $40-80 |
| 深睡功耗 | ~10-30 µA（RTC 唤醒） | 偏高（无低功耗无线场景意义） | 不适合电池长续航牌 |
| 对迷你板适配度 | **完美**：WiFi 拉数据+深睡刷屏 | 不适配（无 WiFi、耗电） | 性能过剩 + 生态死亡 |

**K210 什么时候才值得碰**：当且仅当 ①手头已有 Maix 板只想跑现成视觉 demo（人脸/色块识别，纯教学玩具），②明确不进量产、不依赖后续供货。任何"要做成东西长期用"的立项都不该选它。如果以后真需要边缘视觉（比如迷你板加摄像头做"在座检测"），也不要上 K230——选 ESP32-S3 外接摄像头模块（如 ESP32-CAM 路线）或树莓派 Pico/RK 系列，供应链都是活的。

## 4. 推荐方案 A（最省事，第一款建议走这条）

**LilyGo T5 4.7" E-Paper S3（V2.3 或 Pro Lite）**——一块板含全部：

- ESP32-S3-WROOM-1-N16R8（16MB flash / 8MB PSRAM）+ WiFi/BLE 5
- 4.7 寸 e-ink（540×960，16 级灰，驱动 ED047TC1）
- PCF8563 RTC + 电池接口（JST 锂电）/ 18650 座（老版）
- 例程与库官方 GitHub 齐全（epd_driver / LilyGo-EPD47）
- 自己只补：锂电（1000-2000mAh）、外壳（3D 打印/亚克力）

已知坑（用户评论实测）：屏幕 FPC 排线连接脆弱、电池座紧、触摸版无触摸唤醒、`epd_driver` 缺旋转文本等高级绘制——**固件界面按"整屏重绘"思路设计，不做精细局部增量**。

## 5. 推荐方案 B（最便宜/最教学）

- ESP32-S3 DevKitC-1（N8R8，¥40 级）或合宙 ESP32-S3 核心板（更便宜 ¥25-35）
- Waveshare 2.9" e-ink 模块（GxEPD2 库支持）或 4.2"
- TP4056 充电板 + 3.7V 锂电（¥15 级）；面包板 → 洞洞板 → 外壳
- 总成本约 **¥80-150**

## 6. 固件架构（两方案通用）

```
┌────────────────────────────────────────────┐
│ 配网：首次开机 AP 热点（ESP32 SoftAP）+   │
│      WiFiManager 网页填 SSID/密码          │
├────────────────────────────────────────────┤
│ 主循环（每 N 分钟，N=10~60 可配）           │
│   1. RTC/定时器唤醒深睡                     │
│   2. WiFi 连接（10s 超时，失败直接回睡）     │
│   3. GET 服务器 /api/board/snapshot?token=..│
│   4. 解析 JSON → 渲染位图（整帧绘制）        │
│   5. e-ink 刷新（每 20 次夹一次全刷）        │
│   6. 回深睡（esp_light_sleep/deep_sleep）   │
├────────────────────────────────────────────┤
│ 中断：按键1 立即刷新 / 按键2 翻模式         │
│       / 按键3 显示电量+服务器状态            │
├────────────────────────────────────────────┤
│ OTA：HTTP 固件升级（后续 v2）               │
└────────────────────────────────────────────┘
```

开发栈建议：**Arduino + GxEPD2/WiFiManager/NTPClient**（方案 A 用 LilyGo 的 epd_driver 替换 GxEPD2）；MicroPython 亦可但 e-ink 驱动与深睡控制不如 Arduino 顺手。

## 7. 服务器配套 API（新端点，改动小）

迷你板不需要完整页面，只喂一个小 JSON（复用现有数据源，**不动现有页面路由**）：

```
GET /api/board/snapshot?token=<看板token>
{
  "ts": "2026-09-10T07:30:00+08:00",
  "countdown": {"name": "中考", "target_date": "2027-06-17", "days": 280},
  "period_now": {"name": "语文", "start": "07:30", "end": "08:10"},
  "period_next": {"name": "课间", "start": "08:10", "end": "08:20"},
  "quote": {"text": "...", "author": "..."},
  "battery_warn": false
}
```

- 数据映射：倒计时/课表/每日一句分别来自 zhongkao-widget 同构配置 + 学习Agent daily-quote 服务（服务端聚合一次，板端零业务逻辑）
- 鉴权：新增只读 token（复用 settings 的 api_password 派生或独立 board_token），不暴露主密码
- 校园无外网/隔离网时：板支持预设"离线课表 + 本地倒计时计算"，仅在有网时拉 quote——固件内做，不依赖服务器
- 追加推送（v2 再议）：板定时轮询足够，不需要 WebSocket

## 8. 供电与续航估算（实测前仅作设计依据）

- ESP32-S3 深睡 ≈ 10-30 µA；WiFi 连网+拉取 ≈ 150-250 mA × 2-5s/次；e-ink 刷新 ≈ 30-60 mA × 2-4s（整帧）
- 1000mAh 锂电，每 30min 唤醒一次（约 48 次/天）：
  - 每次活跃 ≈ 4s × 200mA ≈ 0.22mAh → 每天 ≈ 11mAh
  - 深睡 ≈ 20µA × 24h ≈ 0.5mAh/天
  - 合计 ≈ 11.5mAh/天 → **理论 80+ 天**；电池自放电+衰减按 50% 折算 → **实跑 1-2 个月一充**
- 每 10min 唤醒一次 → 约 3-4 周一充；加太阳能贴片（教室窗边）可显著延长，列为 v2 选项
- 结论：**默认刷新间隔 30min** 是"信息够新 + 续航够长"的甜点；考试倒计时场景其实 1 小时一次都行

| 阶段 | 内容 | 工时（人天） | 验收 |

## 10. 决策清单（等用户拍板）

1. 场景确认：真硬件立项？还是先 PWA 顶一阵（零成本）？
2. 预算与到货耐心：整板 T5（¥300 级、海外发货 1-3 周）vs 自组 Waveshare（¥100 级、国内现货快）
3. 屏幕尺寸：2.9"（口袋）／4.2"（桌面牌）／4.7" T5（最省事）／7.5"（班牌挂墙）
4. 是否做 P0 服务器端点（我做，半天）
5. 校园网络形态：有 WiFi？需要 portal/热点方案？→ 决定是否需要离线预设 v1 就做
