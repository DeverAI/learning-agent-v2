## 1. 「假实现」总览（三路合计约 45 项，去重后）

判定口径（可机检）：死代码 / 静默降级成成功 / 恒真条件 / 依赖未加载的库 / UI 有但无事件绑定 / 提示与行为不符 / 参数零读取 / 占位冒充真实值。

**三条「功能整体不成立」级**：

1. **讲题页（Web+Android 共用）核心链路从未跑通** —— 导航状态机闭环死锁（见 §2.1）
2. **focus 页在 Android 上必卡死** —— 文字降级输入是死路（见 §2.2）
3. **focus 页第二/三次学习开不了** —— 开始按钮永久锁死（见 §2.3）

**数据层系统性伪造**（最隐蔽）：检查点通过率恒 100%、学习时长=检查点数×2、纯文字作答被上报为"语速慢+声音小"、停顿检测与语速标签语义错位（见 §3）。

## 2. R6：7 处缺陷修复（已部署，9 端点全 200）

| # | 缺陷 | 机制 | 修法 | 验证 |
|---|------|------|------|------|
| 1 | **`ref_*` 让会话板书永久失效** | `_save_board_svg` 用固定切片 `int(f[6:-4])` 取号，只对 `board_N.*` 成立；而白名单同时放行 `ref_N.*`，`"ref_0.svg"[6:-4]` 是**空串** → `ValueError`，被上层每个 op 的 `except` 吞掉 → 该会话**后续所有板书图形永久失败** | 改正则捕获组 `_BOARD_NUM_RE` | **探针**：有 `ref_0.svg` 时取号成功返回 `board_2.svg` |

| 3 | 引用图恒定 `ref_0` → **跨段覆盖** | `reference_used` 是**每段局部**计数器，旧页 entries 仍按该名引用 → 回看显示最新一题的图 | 新增 `_next_ref_index()` 扫目录取号 | **探针**：0 被占→1，1/2 被占→3 |

| 5 | **`stopSpeaking` 无限递归** | 函数体末尾**无条件自调用**，无 base case → 点"停止"必 `RangeError`，浏览器朗读也停不掉 | 删自调用，改 `speechSynthesis.cancel()` | `node --check` |
| 6 | **讲题页导航死锁** | `planIdx` 全部赋值只有 `-1`；唯一能变 ≥0 的 `enterStep` 只被 next/prev 调用，而 next/prev 依赖 `planIdx≥0` → **闭环**。叠上"步骤列表渲染了但无事件绑定"、"自动朗读开关恒无差异"、"TTS 两分支皆假时直接落空" | 未开始状态统一起点为 (0,0)；步骤列表补 click；假提示改实话；TTS 无能力时明确提示 | `node --check` |

## 3. R7：停止向长期记忆写入伪造值（已部署）

| 机制（修复前） | 修法 |
|----------------|------|
| `analyze_face` 的**一切失败**都返回 `overall_state="engaged"`，而 `"engaged"` 恰好落在「计为通过」分支 → **不用摄像头 = 检查点必过 = 掌握度固定 +0.1**（写进长期记忆） | `DEFAULT_RESULT` 增 `degraded: True`（5 处兜底 return 全覆盖）；`merge_emotion_report` 传播该标记；通过判定改为**要求未降级** |
| 无表情也无语音时 `combined_report` **硬编码** `engaged`（同样计入通过） | 两处占位改为 `overall_state: "unknown"` + `degraded: True` |
| 学习时长 = `total_checkpoints * 2`（与时间无关的合成值）；`created_at/updated_at` 本就在会话 JSON 里却从未使用 | 改用真实时间戳算分钟；算不出传 `None`，**不编造** |
| `update_study_session(pass_rate=None)` 被当 **0** 参与滑动平均（**用"缺失"冒充"低分"**） | `None` = 跳过本次平均；签名改默认 `None`；`total_checkpoints<=0` 时**不做任何掌握度提升**（原来会因 `pass_rate=0` 落到 +0.02 分支凭空加分） |
| 前端每次弹出检查点**预置** `voice_features={speed:'normal',...}`，纯文字作答时算术结果恒 `slow`+`quiet` 且真实上报 | 增 `_voiceUsed` 标记（仅 `onresult` 置真）；无语音则 `voiceFeatures=null` 不上报；三处假默认值全部移除 |
| 停顿检测是**事件计数**（`detectPause` 只在 `onresult` 里调、`lastSpeechTime` 仅 final 刷新）→ `pause_count` = "1 秒后到达的 interim 事件数" | 改**真实定时轮询**（400ms 检查空闲 >1200ms），任何识别结果都刷新 `lastSpeechTime`；`stopListening`/`reset` 清理定时器 |
| 语速用 `transcript.length`（**字符数**）套英文 word/min 的 80/200 阈值 | 改中文「字/分」阈值 150/320 |

**探针**（`_probe_no_fabrication.py`）实测：失败兜底带 `degraded=True`；merge 传播；`None/None` 不再改动 `total_minutes` 与通过率；真实会话时长按时间戳算得 37 分钟。

## 4. 部署流程修复（本轮额外收获）

部署期间服务被**打停两次**（每次约 1 分钟）。根因与修法：

| 尝试 | 结果 |
|------|------|
| `nssm restart` | **打停服务**：STOP 卡在 `SERVICE_STOP_PENDING`，START 不执行 |
| `nssm stop` → 轮询 → `nssm start`（我"修复"后的方案） | **再次打停**：同一个坑；**处方是凭推测下的，没有实测** |
| **强杀 app 进程 → nssm 自动拉起**（最终方案） | **实测通过**：杀 PID → 自动拉起 True → 9 端点全 200 |

关键事实：`nssm get LearningAgent AppExit` 为**空 = 默认 Restart**，`AppThrottle=1500ms`，因此强杀后 nssm 会自动重启。落地脚本 `_remote_deploy.ps1`。
