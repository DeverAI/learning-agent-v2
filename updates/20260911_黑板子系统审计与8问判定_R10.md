## 1. 你要的 8 个问题：逐条判定

| # | 问题 | 判定 | 依据 |
|---|------|------|------|
| 1 | **备课** | **不能** | 板书只有 AI 在讲解时写入这一条路径。board 相关端点只有 2 个（快照 + 资产读取），**没有任何"写入板书内容"的客户端入口**；`start_session` 只接受 mode/topic/question_id，board 固定为空新板；无草稿、无跨会话复用（`list_sessions` 返回字段不含 board）。桌面端同样无"准备一节课"的实体 |
| 2 | **看课** | **部分** | **能**：Web 端多页翻页 + 页码指示 + 快照跳页 + 学生手动存快照，全链路真实（数据来自后端 JSON，非占位）。桌面端能**实时旁听正在上的网课**（WASAPI 环回采集 → VAD → 转写文字流，落盘 `data/classroom/YYYYMMDD.jsonl`）。**不能**：① 跨会话/刷新后回看——`/api/focus/history` 端点存在但**前端零调用**，历史列表也不含 board；② 快照**只存页号不存内容**，而 `clear/erase` 恒作用于末页 → AI "先快照再清屏"时，点开快照看到的是**已被清空**的页；③ 桌面端转写 jsonl **没有任何回放消费方**（唯一读取点是同步器补漏上传） |
| 3 | **陪看** | **能（真实现）** | 桌面端 `classroom_coach`：AI 旁听学生正在上的网课，**发现讲错/跳步就主动补讲**。两条触发链——AI 决策轮询（默认 45s，五级闸门：静音→level→冷却→置信度→级别过滤）+ 学生主动请求 `request_teaching`。讲解词**流式上板** + TTS 朗读 + 朗读前开防自说回环窗口。且有**用户实测后的设计迭代记录**（不再全屏白板遮挡网课 → 右上角局部卡片，自动 30s 清除 + `Ctrl+Alt+H` 手动关闭；字号双向钳制防放大失控） |
| 4 | **临时上课** | **不能** | 无"课"的对象（无 id/标题/开始-结束状态机），也无运行期开课入口："开课"= **应用启动时读设置自动启动监听**，且改动需重启（UI 明确写"改后需重启应用生效"）。`start()/stop()` 可反复调用，但生产端只在启动/退出各调一次。唯一的"临时注入"原语 `push_manual` **无生产调用方**（仅测试）。**旁证**：`lecture_engine` 的 r58 讲题链路（拉题→生成计划→逐步播放）是"可即时开讲"的，但那是**题目讲解**，不是"一节临时的课" |
| 5 | **访问相关内容** | **部分** | Web 端**只有一条**通道：`{"op":"reference"}` 引用**当前题目自带**的原题图/照片（依赖**手填** question_id，无题库选择器、后端不校验 ID 真伪，缺图则降级成一行"[原题图不存在]"）。题库/笔记/知识点**无端点、无前端入口**，entry 类型只有 text/svg/image 三种、**无 link 类型**。桌面端三模块**完全无检索能力**（coach 只用已在本机的转写拼上下文，sync 只写不读） |
| 6 | **把部分位置填充为黑/白板** | **桌面端能 / Web 端不能** | **桌面**：`paint_rect` op → `painter.fillRect(px,py,pw,ph,QColor(op["color"]))`，颜色任意（`#000000`/`#ffffff`/8 位带 alpha），且覆盖窗是 `WindowStaysOnTopHint` + 全屏 + 不透明填充 → **能画在其它应用窗口之上**；另有 `open_page(bg=...)` 可整屏开一块带底色的板。**Web**：`board.ops` 白名单只有 `write(text|function|diagram|shape) / reference / erase / clear / newpage / snapshot`，**无任何 fill/mask/高亮 op**；`clear` 是"清空本页条目"**不是涂白**；shape 的 `rect` 填充与描边**硬编码**（`fill="none" stroke="black"`），不接受颜色参数；前端也无手绘交互 |
| 7 | **视觉审核** | **部分（且真实链路是死的）** | **设计存在且写得诚实**：`placement.py` 有 `MAX_ADJUST_ROUNDS=2` 的限次回路，超限时 `logger.warning("放置自检超限…保持现状")`——**不假装满意** ✓；Web 端 shape/diagram 生成侧有内容级校验（`_has_drawing_content` + 失败占位签名识别）。**但**：① 判定标准其实只是**几何 IoU**（阈值 0.15），不是看图；② 桌面端真实链路**三层断点**导致**一次自检都跑不到**（见 §2）；③ Web 端**无重试、无评分、无视觉模型复核、无整板级质检**（对比：题目示意图链路有 GLM vision review，板书未接入）；④ 前端**只展示"图形加载失败"文案**，`board_summary` 的 `svg_ok/svg_failed/skipped/erased` 全部零读取 |
| 8 | **双端实时处理** | **不能** | `classroom_sync` 的同步物是**课堂笔记 Markdown**（转写文字 + 补讲记录），**不是板书、不是进度、不是状态**；形态是 `QTimer` **默认 30 分钟、默认关闭**的单向 `POST /api/notes`；**无 WebSocket/SSE、无回传**，权威端=桌面端，冲突只靠客户端水位幂等。**板书（overlay ops）完全不进同步**——`classroom_sync` 全文无 overlay 引用，`main.py` 构造 `ClassroomSync(monitor, coach)` 时也没传 overlay；`screen_paint.py` 全文无 Signal/socket |

## 2. 本轮最重的发现：桌面端「视觉选位 + 看图自检」**从未运行过**

`placement.py` 头部宣称「位置选择、避让、看图调整由全模态模型负责」，实际运行时会依次撞上三层断点，**任一都足以让它彻底失效**（三层均已本人复核确证）：

| 层 | 位置 | 问题 |
|---|------|------|
| ① | `screen_paint.py:177` | 用 `_Qt.SmoothTransformation`，但模块只 import 了 `Qt`——**`_Qt` 从未定义**（全仓 grep 仅此一处）。屏宽 > 960（1920 宽屏幕必然）即 `NameError` |
| ② | `placement.py:90` | `from services import ai_service` —— 桌面端运行时 `sys.path` 只含 `desktop/`，而 `services` 包在 `backend/` 下（**`desktop/services` 目录不存在**）→ `ModuleNotFoundError` |
| ③ | `placement.py:109` | `self._ai.xiaomi_vision(...)` 是 **`async def`**（`ai_service.py:1451`）却**没有 `await`** → 拿到协程对象 → `str()` 里没有 `{` → 每轮都返回 `{"action":"place","rect":None,"reason":"no json"}` → **永远回退到硬编码 `{0.54,0.03,0.44,0.32}`** |

失败被上层的 `except` 兜住（`lecture_engine.py:304-306` → "放置代理异常，降级直接渲染"），所以**症状是静默降级而不是崩溃**：卡片永远画在固定位置，视觉选位从未发生。

**已修**：① `_Qt`→`Qt`；② 改用**桌面端自己的** `core.ai_client`（该模块本就有现成的**同步** `vision_chat(prompt, image_bytes)`）；③ 换成同步调用，并把异常显式化（`logger.warning` + 明确 reason），不再静默穿透。
**附带清理**：`placement.py:139-140` 的 `... if o not in occupied_before or True`（`or True` 让过滤恒成立、`occupied_before` 是死变量）；`:147` 的 `and rounds >= 0`（恒真）。

| **临时上课** | "不能——需要'课'的实体与生命周期状态机" | **「临时上课本质就是 AI 讲题的加强版」**；既然都是 LLM，不必担心"能不能讲知识点" | 我把门槛估高了。它**不是**要新建一套课程体系，而是**在既有 `lecture`（讲题）链路上做强化**——即"可即时开讲"本就由讲题链路提供，缺的只是把它当"一节课"来用（多段连讲、可中断、可追问）。**实现成本远低于我先前的判断** |

| **相关内容接入** | "部分（只有 `reference` 引用当前题目原图一条通道）" | **「必须有，毋庸置疑」** | 从"待定/待做"升级为**必做项**。当前现实不变（只有原题图一条通道、题库/笔记/知识点无端点无入口），但**优先级由用户明确锁定** |

**教训（对我自己）**：§1 里"临时上课 不能"这条，是我**按自己的架构直觉**（"要上课就得有课程实体"）下的判定，而用户的意图是"复用讲题链路、别另起体系"。**审计只该回答"代码现在能不能"，一旦越界到"要做什么得先建什么"，就会把简单问题说复杂。** 这条与 §6 的诚实声明同类：**判词要贴着证据，不要替用户设计。**
