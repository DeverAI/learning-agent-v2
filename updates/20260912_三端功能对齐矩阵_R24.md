# 三端功能对齐矩阵（R24，2026-09-12）

> 为什么要这张表：用户点名的第 ① 项是「三端功能对齐」。此前判断三端差异**全靠印象**
> （"安卓是套壳吧""桌面端是不是少一堆功能"），而印象无法指导修复。
> 本表逐行给**代码证据**，只标三类：**✅ 直接用 / ⚠️ 残废（有入口但功能坏） / ⛔ 无入口**。
>
> 三端定义：`backend/`（网页版 + PWA，安卓 App 内运行的也是它）、`desktop/`（PySide6 桌面端）、
> 安卓端 = WebView 壳 + 原生桥（它没有独立界面：能力 = 网页能力 ∩ WebView 支持面 + 原生桥补的洞）。

---

## 一、Android WebView 的能力边界（先定常量，再谈对齐）

| 浏览器能力 | 网页版 | 安卓 WebView | 证据 / 处置 |
|---|---|---|---|
| `<input type=file>` 选图/多选 | ✅ | ✅ | `MainActivity.onShowFileChooser`（非图片走系统选择器） |
| 拍照直拍 | ✅ | ✅ | `prepareCameraIntent` + FileProvider（写入应用私有缓存） |
| `getUserMedia`（摄像头/麦克风） | ✅ | ✅ | `onPermissionRequest` + 同源校验 + 按请求各自权限集判定 |
| 文件下载 | ✅ | ✅ | `setDownloadListener`（限同源 + 带 cookie） |
| 语音**合成** TTS | ✅ Web Speech | ⚠️→✅ | WebView 无 `speechSynthesis`；R23 用 `AndroidTTS` 桥补齐（分片/排队/常亮） |
| 语音**识别** ASR | ✅ Web Speech | ⚠️→✅ | WebView 无 `SpeechRecognition`；**R24 新增 `AndroidSR` 桥** + JS 适配层 |
| Service Worker（PWA 离线） | ⚠️ http 下不可用 | ⛔ | 项目**刻意不用 SW**（`offline.js` 注释写明），离线全靠 IndexedDB 层 → 三端一致 |
| 屏幕唤醒锁 Wake Lock API | ⛔（需 https） | ⛔ | 长时间朗读会熄屏；R23 在**原生侧**用 `FLAG_KEEP_SCREEN_ON` 覆盖朗读场景 |
| 系统通知 Notification API | ⛔（需 https） | ⛔ | 全站未使用；未接原生通知（记为待办，不是缺陷） |
| `navigator.clipboard` | ⚠️→✅ | ⚠️→✅ | **http://IP 不是安全上下文** → 属性为 undefined，原写法**同步抛 TypeError**、按钮点了没反应。**R24 统一走 `$copyText`（execCommand 回退）** |
| 全屏 requestFullscreen | ✅ | ✅ | `questions.js` 对比模式 |

**结论**：安卓端**不是纯套壳** —— 上传/拍照/权限/下载/朗读/识别都有原生实现或桥接；
真正缺的只有「通知」与「网页侧屏幕常亮」，两项都已处理或记录。

## 三、本轮（R24）修掉的三端差异

| 缺口 | 现象（学生视角） | 修复 | 证据 |
|---|---|---|---|
| 安卓无语音识别 | 专注模式点麦克风 →「浏览器不支持语音识别」（诚实降级，但功能没了） | Java `SRBridge`（`SpeechRecognizer` + 轮询事件队列 + 连续错误上限 + 权限回调）+ JS 适配层 `android_sr.js`（与 Web Speech API 同形） | `MainActivity.java`、`static/js/android_sr.js`、`base.html` |
| 专注模式无声音 | 服务器配音不可用时 App 内**完全静音**（讲课页早接了原生桥，专注模式没接） | `browserSpeak` 增加 `AndroidTTS` 优先分支；`stopSpeaking` 同步停原生 | `static/js/focus.js` |
| 复制按钮全废 | http://IP 下所有「复制」按钮点了没反应（非安全上下文） | 新增 `$copyText`（Clipboard API → `execCommand` 回退），5 处调用点全部接入 | `static/js/app.js`、`questions.js`、`paper_detail.html` |
| 笔记看不到关联题目 | 题库「存笔记」后，笔记里看不到那道题，正文还残留裸标记 `[[QUESTION:id]]` | 建笔记后补 `POST /api/notes/{id}/references`；笔记「题目」栏新增**关联题库题目**卡片 + 跳回题库 | `static/js/questions.js`、`templates/notes.html` |
| 图的质量无人检查 | 生成的示意图即使线条不可见也「一切正常」 | 编辑器保存后自动调 `/api/diagram/check`，有问题当场提示 | `static/js/editor.js` |

## 四、仍未对齐 / 未验证（诚实清单）

1. **画布编辑器触屏拖拽未真机验证**：代码有 `touch-action:none` 与指针事件，但没在安卓真机跑过。
2. **系统通知**：三端都没有（未使用）；若要做「任务完成提醒」，需要原生通知桥。
3. **网页端屏幕常亮**：讲课/专注在网页版与手机浏览器仍会熄屏（Wake Lock 需 https）；桌面端与安卓端已覆盖。
4. **桌面端页面级缺口**（题库/笔记/组卷/批改无独立界面）：属**定位差异**，非缺陷；
   若希望桌面端更接近网页版，需专门设计（直接嵌 WebView 会与现有侧栏交互冲突）。
5. **平板/分屏断点的真实表现**：只有 CSS 规则与静态扫描（R24 新增 `backend/audit_layout.py`）保证，无真机截图验证。
