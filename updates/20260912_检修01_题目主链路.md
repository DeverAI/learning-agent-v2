## 二、结论：这条链路**整体是扎实的**，但有三处"静默降级"

先说要肯定的地方（这些都是**实测读过代码确认的**，不是文档说的）：

| 项 | 结论 | 证据 |
|---|---|---|
| 上传校验 | **三重校验，不是只验扩展名**：`content_type` 前缀 + 扩展名白名单 + **真实字节签名**（JPEG/PNG/WEBP magic） | `routers/ocr.py:116-128`、`:107-109` |
| 大上传 | **分块读 + 边读边判**，超限立刻 413，内存峰值封顶（不是"先全读再拒"） | `services/upload_guard.py:23-44` |
| 路径穿越 | 文件名**从不参与路径**（只取白名单扩展名，落盘固定名）；`/storage/**` 逐段白名单 + `realpath/commonpath` 包含性校验 | `ocr.py:118-119`、`main.py:337-380` |
| 重复触发 | DB CAS 抢占 + 进程内按题锁 + 终态跳过，三重防护 | `ocr.py:647-655`、`ocr_service.py:149-183` |
| 重启对账 | **存在**：先把 stale `pending/processing` 标 error，再按状态文件续跑 | `ocr.py:207-285` |
| 失败终态 | 外层 `except` 兜底把题目和任务一起标 error，不留"任务失败但题目还在转" | `ocr_service.py:858-868` |

**要修的是这三处**（都属于"允许降级，但不该静默降级"）：

### 缺陷 1（最重）：切题降级标记会被成功流程删掉

`_mark_split_fallback()` 把 `split_fallback` 写进 `storage/task_states/{qid}.json`，
而 `_clear_task_state()` 在任务**正常完成时把这个文件删掉**。

用户现象：上传一整页 5 道题 → 切题失败 → 静默按 1 道处理 → 任务成功 → 标记消失
→ **题库里只有 1 道题，题干是整页，且没有任何提示**。

代码注释自己承认了这一点（"常驻的用户可见告警需要 DB 字段或任务面板支持，待产品决策"）——
即**知道但没做**。本轮补上。

**修法**：同时写进 DB 的 `audit_flags`（`Question` 表已有该列，前端会渲染成徽标）。

### 缺陷 2：多图一题时，单张图识别失败被吞

`ocr_service.process_image` 对题干图与辅助图**逐张循环**，每张外面套
`except Exception: logger.warning(...)` 后继续（`:246-251`、`:274-285`）。

后果：`ocr_text` 由成功那几张拼成，**静默少一块**；但后续非空检查照样通过 → 题目判 `done`。
辅助图（解析/手写作答）失败则用户的参考答案**静默丢失**。

**修法**：收集失败清单，在终态写库时落 `ocr_partial_failure` 标记（状态仍判 `done`，因为内容可用）。

### 缺陷 3：前端丢弃后端返回的 `rejected`

后端 `POST /api/ocr/batch-process` 返回 `{message, count, rejected}`（被跳过的题：
已在处理中/已锁定/状态不允许），前端只弹 `r.message`。

用户现象：**提示"已启动 5 道题的处理"，实际只有 2 道在跑，另 3 道无声消失。**

**修法**：前端合并出"另有 N 道被跳过"（`warn` 提示）。

## 三、改了什么（逐条）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `services/audit_service.py` | `FLAG_TYPES` 新增 `split_fallback` / `ocr_partial_failure`；把写死的保留白名单提成模块级 `_PRESERVED_FLAG_TYPES` 并纳入新类型 |
| 2 | `routers/ocr.py` | 切题降级时 `await flag_question(..., "split_fallback", ...)`；**留痕失败单独 try/except 记日志**，不影响识别本身 |
| 3 | `services/ocr_service.py` | 新增 `ocr_failures` 收集两条循环的失败；`done` 分支写入 `ocr_partial_failure` 标记 + `logger.warning` |
| 4 | `static/js/questions.js` | 新增 `_degradedBadge(q)`（「切题降级」/「识别不全」徽标），接到移动端卡片与桌面端行**两处**渲染；`rejected` 提示 |
| 5 | `templates/batch_upload.html` | `rejected` 提示 |
| 6 | `backend/test_r19_ocr_degrade.py` | 新增 9 条断言 |

**为什么缺陷 1 的修法要特别小心**：`audit_service` 里那个保留白名单原先写死成三元组，
**新类型不加进去就会被夜间自动重写清掉** —— 现象是"标记出现过一会儿又没了"。
所以本轮把它提成常量并加了测试，避免下次再加标记时重蹈。
