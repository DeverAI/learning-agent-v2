## 2. 用户点名「工具执行完毕召回 Agent 继续工作」：原来只做了一半

**现状（读码确认）**：后台任务卡片有进度、取消、「接着做」，但任务 `done` 之后
**只显示一行「任务已完成」** —— 前端不通知 Agent，后端也没有任何把产出注入会话的路径。
用户必须自己开口问「课备好了吗」，「召回继续工作」这句话在实现上是缺的。

### 已实现（三段）

| 段 | 落点 | 关键设计 |
|---|---|---|
| 工具 | `agent_tools.h_task_recall` + 工具表登记 | 读**任务真实产出**（不是前端传的摘要），按工具类型组装摘要；非 done 状态**拒绝**（防讲出不存在的结果） |
| 路由 | `routers/sessions.py` `[系统召回]` 前缀旁路 | **不经过意图分类器**：省一次调用、零误路由；前缀与 task_id 正则提成模块常量，前后端共用同一来源 |
| 展示 | `templates/agent.html` | 卡片终态自动召回**一次**（去重表）、**跨会话不误召**、聊天区出现「召回 → Agent 已被召回继续讲解…」芯片 |

**测试钉住的边界**：任务不存在 / 任务没完成 / 重复轮询不重复召回 / 卡片属于别的会话不召回 /
前端拼的消息格式能被后端正则解析（跨文件契约，两侧断言同一常量）。

## 3. 鉴权：改一次密码就会全站 401（且没有任何入口去改）

**读码事实**：`$API._authToken` 直接硬编码 `"Ntmhzsgtc"`；`main.py` 的 password_guard
在设置了 `api_password` 时对所有 `/api/*` 强制比对。也就是说：
**学生一旦把密码改成别的，整个前端（含安卓端）全部 401，而且没有登录页可以输入新密码。**
（本机实测：settings.json 里的密码恰好等于默认值，所以一直"看起来正常"。）

### 已修（`static/js/app.js`）

- token 优先从 `localStorage['la_auth_token']` 读，硬编码默认值退化为兜底；
- `_parse` 对 401 打 `needAuth` 标记；
- `_request` 捕获后**弹一次密码框 → 存 localStorage → 原请求重试一次**（`_retried` 防死循环，
  `_reauthPromise` 去重防并发弹一堆框）；
- 401 由中间件在**端点执行之前**返回，因此重试不会造成重复提交（这一点写进了注释与测试）。

**未做（记录）**：设置页改密码的入口仍未提供（改密码目前要动服务器 settings.json）。
但有了本次修复，「改完密码后前端能自己问一次并记住」，已经不是死路。

## 4. 拍题 / 搜题 / 画图 / 笔记管线：后端扎实，断在「题 → 笔记」

**先说结论**：这条管线的**后端**质量确实高（不是文档说的，是本轮逐行读的）：

| 环节 | 结论 | 证据 |
|---|---|---|
| 搜题上传 | `content_type` + 扩展名 + **真实字节签名**三重校验；分块读边读边判 | `routers/search.py:87-102`、`upload_guard` |
| 多题切分 | 超容量**显式报错**不切片（30/80 道上限）；子题目录失败**整体回滚 + 清目录** | `search.py:139-231` |
| 相似度 | difflib + 标签/学科加分；AI 精排；**NaN 显式跳过**（`math.isfinite`） | `search.py:234-301` |
| 入库抢占 | 原子 `UPDATE ... WHERE status='search_done'` + rowcount 判定防双跑 | `search.py:569-583` |
| 恢复描述 | 提交可见状态**前**先写 task_state，进程退出不留"永久处理中" | `search.py:449-478` |

**断点（实锤）**：`questions.js` 与 `editor.js` 对 `/api/notes` **零调用**。
学生想「把题库里这道题整理进笔记」，唯一路径是绕到批改中心去「另存为错题」。

### 已修：题库列表一键「存笔记」

- 桌面表格行与移动卡片**两处**都加按钮（三端一致：手机/电脑都能用）；
- 只用 `done` 状态的题（未完成的题干可能是半截）；
- 内容是**确定性搬运**（`[[QUESTION:id]]` 引用标记 + 题干 + 标准答案 + 知识点），
  不消耗模型额度；AI 整理仍归笔记页的 auto-organize；
- 存完给出「去笔记页打开它」，并**补上笔记页 `?note=<id>` 深链**（否则那个跳转是空诺）。

## 7. 安卓端：比预期扎实，修三处真问题

**先说好的**（都是本轮读码确认的，不是文档）：文件上传 + 拍照直拍（FileProvider）、
`getUserMedia` 权限桥（同源校验 + 按请求各自权限集判定）、下载同源限制、
原生 TTS 桥、`onShowFileChooser` 非图片走系统选择器、错误浮层 + 重试 + 改服务器、
生命周期清理、UA 标记驱动网页紧凑模式。**它不是纯套壳**。

### 已修

| 问题 | 现象 | 修法 |
|---|---|---|
| TTS 单段上限 4000 字符 | 长讲解词超限**静默失败**：后文不读、无提示 | `splitForTts()` 按 3000 字符在句子边界切分，多段 `QUEUE_ADD` |
| TTS 初始化竞态 | `init` 是异步的，页面刚进来就 `speak` 会被丢弃 → **第一句没了** | `pendingTtsChunks` 排队，`flushPendingTts()` 在 init 成功后补读；`isSpeaking()` 把排队也算"在说" |
| 讲课中屏幕变暗 | 学生在看讲解文本，屏幕照样熄 | `speak()` 自动开 `FLAG_KEEP_SCREEN_ON`，`stop()` 关（经桥转发到 UI 线程） |

版本号 `versionCode 5 → 6`（`versionName 1.4 → 1.5`）。**APK 需要重出**（见 §9）。

**安卓端待办（记录，未动）**：WebView **不支持 Web Speech API**，所以语音输入
（`webkitSpeechRecognition`）在安卓端**必然不可用**；讲课朗读已由原生 TTS 桥覆盖，
但「语音提问」要么接原生 `SpeechRecognizer` 桥，要么在 UI 上明确隐藏入口。
