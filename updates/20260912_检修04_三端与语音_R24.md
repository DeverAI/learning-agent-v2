## 2. 安卓语音识别桥（R24 主线）

**问题**：Android WebView **不实现 Web Speech API**（合成与识别都没有）。合成早就有 `AndroidTTS` 桥，
识别一直没有 → `focus` 模式的「语音作答」在 App 里**恒定不可用**（页面诚实降级成文字输入，但功能就是没了）。

**实现**：
- Java 侧 `SRBridge`（`MainActivity.java`）：`SpeechRecognizer` + 中文 `RecognizerIntent` +
  **轮询事件队列**（`pollEvents()` 返回 JSON 数组）。为什么不用 `evaluateJavascript` 回注：
  中文文本与引号在拼 JS 字符串时极易二次转义出错。
- 权限：`RECORD_AUDIO` 未授权时先申请（`REQ_SPEECH`），拒绝则回 `not-allowed` 事件 —— **不静默失败**。
- 稳健性：`SR_MAX_ERROR_STREAK = 5` 防"没听清"时无限重启空转；`onDestroy` 里 `destroy()` 释放麦克风。
- JS 侧 `static/js/android_sr.js`：把桥包装成**与 Web Speech API 同形**的构造函数
  （`onresult/onerror/onend` + `results[i][0].transcript` + `results[i].isFinal`）。
  于是 `focus.js` 只改了**能力探测与构造函数选择**两处，其余识别逻辑（累积 final、interim 预览、
  停顿检测、语音特征上报）**一行未动**。
- 设备前提：若手机没有识别服务，`isRecognitionAvailable()` 返回 false → 适配层不注入 → 回落到
  原有的诚实降级文案。**不假装能用**。

## 4. 复制按钮：一个"本地永远复现不了"的 bug

`navigator.clipboard` 只在**安全上下文**（https / localhost）存在。生产是 `http://<IP>:8000` →
该属性为 undefined → 原先的 `navigator.clipboard.writeText(...)` 在**取属性那一步就同步抛 TypeError**，
连 `.catch` 都进不去：按钮点了**没有任何反应**。而本地 `127.0.0.1` 开发时它永远正常。

**修复**：全局 `$copyText`（Clipboard API → `execCommand` + 临时 textarea 回退），5 处调用点接入
（`app.js` 2 处、`questions.js` 3 处、`paper_detail.html` 1 处）。
**并写进扫描器规则**（见 §7），以后谁再裸调 `navigator.clipboard` 会立刻红。

## 5. 管线补口：笔记 ← 题目 有去有回

R23 加的「存笔记」只写了 `question_ids`，**没登记 references** —— 而
`resolve_note_references()` 只替换**在 references 里出现过**的标记，所以学生打开笔记看到的是
一行裸文本 `[[QUESTION:abc123]]`。本轮修两处：
1. 建笔记后补 `POST /api/notes/{id}/references`（并如实提示"引用未登记"这一失败分支）；
2. 笔记详情「题目」栏新增**关联题库题目**卡片（此前只显示 AI 提取的 `typical_questions`，
   从题库建的笔记在这一栏是空的），可一键跳回 `/questions?qid=…`。

> 这条是 R23 自己留下的洞，被 R24 写"反向显示"时对照代码发现 —— 说明**写完功能要回头看它的两端**。

## 8. 出包：一个被误诊两次的构建问题

**现象**：`gradlew.bat assembleDebug` 抛
`java.lang.ClassNotFoundException: org.gradle.wrapper.GradleWrapperMain`。

**我先入为主地当成"中文路径"问题**（R14 记的就是这条），于是按用户授权把 `android/` 复制到
ASCII 临时路径 `%TEMP%\la_android_build` 再构建 —— **同样报错**。

**由此推翻旧结论**：与路径无关！wrapper jar 本身完整（能 `jar tf`、含 `GradleWrapperMain.class`）、
Gradle 8.2 发行版也已在本机（`~/.gradle/wrapper/dists/gradle-8.2-bin/...`）。
真正可用的路子是**绕开 wrapper、直接用发行版的 `gradle.bat`**：一次成功
（`BUILD SUCCESSFUL in 49s`，31 个 task 全执行）。

**核验（不只看"构建成功"四个字）**：解包 `classes*.dex`，按 Latin-1 扫描确认新符号确实进包：
`AndroidSR / pollEvents / SRBridge / splitForTts / TTS_CHUNK_LIMIT / AndroidTTS / LearningAgentApp` 全部 True。
（`FLAG_KEEP_SCREEN_ON` 为 False 属正常：`static final int` 会在编译期内联，名字不进 dex。）

> 另外记一条操作经验：PowerShell 把 gradle 写到 stderr 的 **deprecation 提示**当成
> NativeCommandError → 进程退出码 1，看起来像"构建失败"。判断成败要看 gradle 自己的
> `BUILD SUCCESSFUL` 行 + 产物时间戳，不能只看 exit code。
