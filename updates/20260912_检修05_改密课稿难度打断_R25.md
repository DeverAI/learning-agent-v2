## 1. 设置页改密码（R23/R24 遗留的「只能手改服务器文件」）

**问题**：`api_password` 只能改 `settings.json`；改密后其他设备靠 R23 的 401 补密兜底，但**没有入口**。

**实现**：
- `POST /api/settings/password`：验当前密码 → 设/改/关（新密码留空 = 关闭鉴权）。
- `GET /api/settings/password/status`：只回 `has_password`，不回密码。
- 环境变量 `LEARNING_AGENT_PASSWORD` 优先时**拒绝改密并如实说明**（改了也不生效）。
- 设置页新卡片：当前/新/确认三栏 + 状态提示；成功后本机 `localStorage` token 同步更新。

**测试钉住**：设密 → status 真/错误当前密码 400 / 两次不一致 400 / 正确改密 / 关密 / 过短 400。

## 2. 课稿独立页面（提前备课：保存后离线观看）

**问题**：课稿只有 Agent 对话工具 + HTTP API，**没有页面**。学生备完课想自己看，只能让 Agent 念。

**实现** `GET /lessons` + `templates/lessons.html`：
- 列表（完成度进度条）/ 详情（分片可直接改讲解词）/ 定稿 / 删除 / `?lesson=<id>` 深链；
- **「缓存离线」**：强制完整 `GET /api/lessons/{id}?max_chars=200000`，让 `offline.js` 写入 IndexedDB；
- 侧栏「管理」下新增「课稿」入口；Agent 的 `lessons_list` 卡片改为可点链接。

**与离线层的关系**（Android WebView 同样走这条）：
- 项目**刻意不用 Service Worker**（http://IP 下不可用），离线全靠 IndexedDB（`offline.js`）；
- `/api/lessons` 早已在 GET 缓存白名单（R23）；本页补的是**主动缓存入口**与阅读 UI；
- 断网时打开课稿页：列表与详情读缓存；写操作仍诚实失败或排队。

## 5. P4 打断判定（cancel / keep / observe）

**问题**：双端架构里的「打断三态」一直待办；学生在后台备课时说「取消」可能被分类成 chat，任务继续烧额度。

**实现**（路由层确定性，**不走分类器**）：
- 仅当本会话有 `running`/`pending` 后台任务时启用；
- **cancel**：命中取消词 → 对全部活动任务 `request_cancel`，文案写明协作式/25 秒兜底；
- **keep**：命中继续词 → 只提示任务仍在跑；
- **observe**：不拦截，继续分类（避免把正常提问吞成打断）。

**已知边界（写进测试）**：「这道题怎么取消分母」也会命中 cancel。当前策略：宁可误取消也不烧额度；若将来误伤再收紧为句首/独立成句。

## 7. 失误与自纠

1. **`anyio.run(coro)` 不能直接传 coroutine 对象**（要传可调用）——第一版测试整页红；改为 `asyncio.run` / 可调用包装。
2. **插入 `_try_interrupt_running_tasks` 时误删了 `_session_chat_impl` 的 def 行**——读回文件发现函数体悬空，立即补回（改前已备份）。
3. **`list_tasks` 返回的是 dict（`tasks` 键）不是 list**，且任务主键字段是 `task_id` 不是 `id`——按真实签名改消费方，避免「看起来在跑其实没列出任务」。
4. 密码测试会污染后续用例：模块 fixture 收尾强制清空 `api_password`。
