# 2026-09-12 R17–R19：把标准提到「撑过初三」，然后发现系统是空的

> 触发：用户说「我要靠这个项目撑过初三的知识补漏、自招学习等内容，你应该就能理解我们的项目要做到什么程度」。
> 我按那个标准做了两件事：**查清为什么生成不出内容**，以及**数清里面到底有多少能用的东西**。
> 结论一好一坏，都记在下面。

---

## 一、好消息：备课写不出内容，根因找到并修好了（R17）

### 根因

打原始 API 实测。本项目主力模型 `deepseek-v4-pro` 是**推理模型**：先产出
`reasoning_content`（思考），再产出 `content`（正文）。同一个备课 prompt：

| max_tokens | finish_reason | reasoning_tokens | 正文长度 |
|---|---|---|---|
| 2048 | `length` | 2048（吃满） | **0** |
| 8192 | `stop` | 3336 | **1404** ✓ |

**写 1500 字的课稿，光"想"就要 3300+ tokens。**

**而这 2048 是我自己 R15 调出来的**：当时按"6000 字正文太长会撞上限"的**直觉**从 4096
下调到 2048 —— 方向完全反了，撞上限的是 reasoning，不是正文。

### 修复

| 改动 | 位置 |
|---|---|
| 单片预算 2048 -> **8192** | `lesson_service.SECTION_MAX_TOKENS` |
| 空正文重试**至少跳到 8192**，不再只 `×2` | `ai_service.REASONING_SAFE_MIN` |
| 空正文日志带上 `completion_tokens` / `reasoning_tokens` | `ai_service._call` |
| 回归测试改为按真实阈值断言 | `test_delivery_regressions.py` |

最后一条值得单说：既有的 `test_empty_reasoning_response_retries_with_larger_budget`
断言写成 `calls == [128, 512]`，等于把 **"512 就够"** 这个**已被实测推翻的假设固化成契约**。
所以我调小预算时**测试全绿**、生产上却一片课稿都写不出来——**测试保护了错误的东西**。
现在 mock 改成"预算 < `REASONING_SAFE_MIN` 就拿不到正文"，这类退化会被拦住。

### 生产验证（修复后重跑同一条 E2E）

```
最终状态 = done  进度 = 100  filled_now=2  empty_sections=0
#0 '勾股定理核心模型梳理'  1501 字
#1 '收尾实测易错题讲评'    1097 字
VERDICT = 备课能写出内容
```

内容质量也站得住（「…不少同学直接写 5。为什么错？因为题目说的…」），是能直接拿去讲的东西。

## 二、坏消息：系统里**几乎没有内容**，而且知识体系根本不存在

### 家底实测（只读）

| 项 | 服务器（你实际用的） | 本地开发机 |
|---|---|---|
| 题库 questions | **1**（一道初二测试题，已锁定） | 5（0 道有知识点标签） |
| 笔记 notes | **0** | 2 |
| 试卷 / 批改 / 课稿 | **0 / 0 / 0** | 0 / 0 / 0 |
| 知识图谱 `knowledge_graph.json` | **文件不存在** | **文件不存在** |
| 知识树 `knowledge_tree.json` | **0 节点** | 7 节点 |
| 学习记忆 `hippocampus/profile.json` | **文件不存在** | **文件不存在** |
| 会话文件 | **0** | 2 |

三条直接推论：

1. **所有基于题库/笔记/知识点/记忆的功能都在空转** —— 答题、组卷、找相关内容、薄弱点复习，
   全都没有输入。继续加功能只会让空壳更大。
2. **`hippocampus/profile.json` 在服务器上不存在** → 专注模式/讲题**从来没在服务器上产生过学习记录**。
   这套东西还没被真正用来学习过一次。
3. **知识图谱文件根本不存在** → "知识补漏"缺骨架：补漏要回答的第一个问题是
   「我这个知识点不会，**该先补哪个前置**」，没有体系与前置边就无从回答。

### 子 Agent 穷尽排查的结论（只读）

- **没有任何学科知识点清单/教材目录/课标数据**（关键词与目录都穷尽搜过）。
- 图谱原有 8 种关系**全是非时序**的，**没有任何前置/先后建模**。
- 唯一像体系的是 `knowledge_tree.json` 的 7 个节点 —— 那是 2 篇笔记**临时生成**的展示树，不是体系。
- `Question` 表**没有难度字段**，难度只存在于提示词文案里 → 自招分层没有数据基础。
- 好消息：**写入管道已存在**，`add_note_to_graph` 的 `relation` 不做白名单校验，
  所以灌体系只需要造**数据**，不需要新写一条路径。

## 三、R18：从零建体系，并把它变成「今天该补什么」

### 1) 课程体系数据（新增）

`backend/data/curriculum_cn_junior.json` —— 初中**数学/物理/化学**知识点 + **前置依赖**：

```
学科 3 ｜ 知识点 206 ｜ 前置边 211
难度分布：基础 56 / 中档 105 / 难 41 / 自招 4
```

每个节点带 `subject / grade(七上…九下) / module / band(基础|中档|难|自招)`，`prereq` 是前置知识点。

**设计取舍**：前置关系按**逻辑依赖**给（"要会一元二次方程，先得会完全平方公式与平方根"），
**不依赖教材版本**，所以换成人教/北师大/苏科版都仍然成立。这是一份 v1 草稿，可增删。

### 2) 校验：写错必须报错，不许静默丢边

`curriculum_service.validate()` 会抓四类问题并**拒绝灌库**：
前置 label 拼错、label 重复、自环、前置成环。

**为什么这条特别重要**：静默丢掉一条前置边，用户会拿到一个**错误的补漏顺序** ——
比直接报错危险得多。校验不过时**一个字节都不写**（有测试钉住）。

### 3) 灌库与查询

- `merge_curriculum()`：按 `(from,to,relation)` 去重、**不跑**"同簇推断"（体系边是精确依赖，
  混进推断关系会把顺序搞脏）、幂等、带 `tag` 可整体撤回（`remove_curriculum`）。
- `get_prerequisites(node_id, depth)`：顺 `prerequisite` 边回溯，按层返回，
  同一节点只出现在**最早**那一层（最短距离），环自然截断。

**实测（服务器上）**：`prerequisites_of("一元二次方程")` 给出 **3 层 / 10 个前置**，
`study_order` 由远到近是：

```
1 整式加减与合并同类项(七上)  2 相反数与绝对值(七上)  3 同底数幂的乘法(八上)
4 有理数加减法(七上)          5 幂的乘方与积的乘方(八上) 6 有理数乘除法(七上)
7 整式的乘法(八上)            8 有理数乘方(七上)        9 完全平方公式(八上)
10 平方根与算术平方根(七下)
```

**这是这个系统第一次能回答「我要学 X，之前该先补什么」并给出可执行的顺序。**

### 4) 今日补漏清单

`build_review_plan(subject, grade, limit)` 把三样东西合成一份清单：

| 排序依据 | 性质 |
|---|---|
| 有错题的知识点优先 | **事实**（题库里确实有被标记/出错的题） |
| 掌握度低的优先 | **估计值**（海马体按遗忘曲线衰减后的值） |
| 其余按 grade / band 由易到难 | **事实**（体系里就这么标的） |

返回体里每项带 `evidence` 字段（`has_wrong_questions` / `has_mastery_record` /
`curriculum_only`），并明确写"掌握度为 null 表示**没有数据**，不是掌握度为零"。

`grade` 参数**不给默认值是有意的**：默认从七上开始对（补漏本就该从最早的缺口补），
但要不要只看当下年级，由用户决定，不替他决定。

### 5) 新增端点与工具

| 端点 | 用途 |
|---|---|
| `POST /api/knowledge-graph/seed-curriculum` | 灌库（幂等；校验不过返回 400 且不写） |
| `GET /api/knowledge-graph/curriculum` | 按学科/年级/难度列出体系知识点 |
| `GET /api/knowledge-graph/prerequisites?label=` | 「学这个之前要先会什么」 |
| `GET /api/knowledge-graph/review-plan` | 今日补漏清单 |

Agent 工具新增 `review_plan`（总数 27 -> **28**），`knowledge_lookup` 增加 `mode=prereq`。

## 四、顺手抓到并修掉的三个真实缺陷

| # | 缺陷 | 为什么一直没被发现 |
|---|---|---|
| 1 | **`h_knowledge_lookup` 把 `graph["nodes"]`（dict）当 list 遍历** → `str.get` 抛 `AttributeError` | **图谱为空时完全看不出来**：空图谱走的是"一个节点都没有"的提前返回，永远碰不到那行。而服务器上图谱文件本来就不存在，所以怎么点都是友好提示 |
| 2 | **`_REL_LABEL` 上方写死的话术**「图谱**没有**前置知识/后继知识语义」 | 在没有前置边时它是**对的**；一旦补上前置边，它就成了**错误信息**。已改成按事实分情况说：有前置边就给方向说明，没有才说没有 |
| 3 | **`add_note_to_graph` 的边去重键只有 `(from,to)`** | 同一对节点之间的第二种关系会被静默丢掉（体重 +1 了，关系却没增加）。例如先写「A 包含 B」再写「A 与 B 相关」，后者直接消失 |

第 1 条有专门的回归测试组 `test_r17_agent_graph.py`，**且刻意用非空图谱**——
用空图谱测等于没测。已实测确认旧写法在非空图谱上必然抛
`AttributeError: 'str' object has no attribute 'get'`。
