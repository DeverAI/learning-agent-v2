# 本轮已完成任务（2026-09-06 傍晚，PWA 离线增强轮）

> 路线 A（用户拍板）：本地只读缓存 + 上传队列 + 服务器处理。关键架构决策：**不依赖 Service Worker**——服务器经 `http://IP:8000` 访问，浏览器安全上下文限制使 SW 不可用；离线层实现在 `$API` 请求封装层（IndexedDB），HTTP 明文环境同样生效。升级 HTTPS 域名后可平滑替换为 SW（记 FUTURE）。

## 实现内容

### offline.js（新文件，backend/static/js/offline.js，先于 app.js 加载）
- IndexedDB（库名 `la_offline`）：store `cache`（url 键，GET 响应缓存，200 条 LRU）+ store `queue`（上传队列，FormData entries 序列化，File 可克隆）。
- GET 白名单（network-first）：/api/questions、/api/papers、/api/notes、/api/banks、/api/profile、/api/daily-quote、/api/system-messages、/api/knowledge-graph；离线回退缓存并 toast 明示"展示离线缓存数据"（响应头 X-Offline-Cache:1）。
- 上传队列白名单（离线入队）：/api/ocr/upload*、/api/notes/upload-images、session upload、search/upload、correction/upload；入队后抛"已加入队列，联网后自动上传"，页面 catch 统一提示；非白名单写操作离线明确拒绝。
- 重放：online 事件 + 启动补传 + 60s 定时；`_replaying` 在飞守卫防并发重复上传（三条触发路径并发）；retries≥5 停自动重试；同步完成 toast 计数。

### 挂接与基础设施
- app.js `_request` 重构：拆 doFetchRaw（原始 Response，网络层错误打 `err.isNetwork` 标记）与 doParse 两回调分派给离线层；在线路径行为不变；offline 未加载时走原逻辑。
- main.py：`/manifest.webmanifest` 路由（PWA 安装：名称/图标/standalone 形态）；render_template 注入 enable_offline；config.py ENABLE_OFFLINE_CACHE 开关。
- base.html：manifest link + offline.js 引入均按 {% if enable_offline %} 条件化（offline.js 在 motion/app 之前）。
- 图标：backend/static/icon-192.png、icon-512.png（PIL 生成"学"字图标）。

## verifier 终检（FAIL → 修复转绿）

1. 【高·已修】GET 回退不区分网络层失败与 HTTP 4xx/5xx——服务器错误被旧缓存静默掩盖。修：doFetchRaw 打 `err.isNetwork` 标记，仅网络层失败回退缓存，HTTP 错误原样抛出；回退时 toast 明示离线数据。
2. 【中·已修】replay 无在飞守卫，三触发路径并发导致同一队列项重复上传。修：`_replaying` 守卫。
3. 【低·已修】replay 中 4xx 与 5xx 分支逐字相同、`!==429` 死区分：合并统一计数保留。
4. 【低·不修·记录】retries≥5 项滞留队列无提示（防丢数据优先，可接受）；入队提示走红色错误 toast（消息文本已自说明）。
